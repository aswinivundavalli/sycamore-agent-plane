Trade-offs and path to scale

Deliberate trade-offs

Zero dependencies, one process. Nothing to install and a single system to reason about. Polling is sufficient at single-workstation scale.
Agents outlive the control plane. No work is ever lost to a restart. During an extended outage, spend caps remain the guardrail.
Agent-agnostic question protocol. Works with any headless agent, and depends on the agent following it. Detecting free-form questions is on the roadmap.
Independent verification. Results never rest on the agent's own claims. Verification of the merged result comes next.

Scaling to a team: ten engineers, hundreds of runs a day

Single host → distributed workers
Workers speak the same runner and event-log protocol, with logs streamed to central storage and runs placed by available capacity.
Process checks → leases
Postgres with heartbeat leases replaces local process checks. The same compare-and-set transitions carry over unchanged.
Merge buttons → merge queue
At volume, the target moves constantly. A queue rebases, verifies the merged result and lands one change at a time.
Single user → identity
Authentication, run ownership, handoff between engineers and a complete audit trail of every merge.
Polling → event streaming
Server-sent events with per-run deltas, and mobile push triggered by the same attention transition.
Local disk → managed storage
Sparse checkouts and a shared object store, with quotas enforced before capacity is exhausted, not after.
