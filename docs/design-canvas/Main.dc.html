Conductor · System design

A single control plane for every coding agent you run

Engineers now run several coding agents in parallel, spread across terminals and machines. Without a shared view, questions go unanswered, finished work waits unreviewed, branches collide and abandoned worktrees exhaust disk. Conductor gives every agent run one place to be launched, observed and reviewed.

Objective

Answer, at a glance, the one question that matters: which runs need a decision from me right now?

Scope

One engineer on one workstation, running several agents concurrently against local Git repositories. Claude Code runs headless today; any agent that emits a structured event stream fits behind the same adapter.

Design principles

The database is the system of record. Every state change is an atomic compare-and-set. Agents never depend on the control plane staying up. Nothing resumes without an explicit decision.

Attention, not activity, orders the board

1 · Awaiting your answer 2 · Ready to merge 3 · Conflicts or failing tests 4 · Failed or interrupted 5 · Stalled 6 · In progress

Every run carries a one-line account of what its agent is doing now, such as “Editing textkit/core.py” or “Running: pytest -q”. It is derived deterministically from the agent's own event stream, with no extra model calls and no need to open a log. The browser tab shows how many runs are waiting on you.

Core capabilities

  • Launch a run from a repository and a plain-language task
  • Isolate every run in its own Git worktree and branch
  • Live state and current activity for every run
  • Review the diff, the agent's summary and an independent test run; then merge, keep the branch or discard
  • Full recovery from a control-plane crash, including kill -9
  • Guaranteed clean-up of worktrees and branches

Operating at scale

  • Attention ranking puts decisions ahead of activity
  • Agent questions reach you; your answer resumes the same session
  • Overlapping edits flagged while runs are still in flight
  • Notifications only when a run newly needs you
  • Per-run spend caps, stall detection and hard timeouts
