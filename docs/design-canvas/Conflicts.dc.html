Concurrent edits to the same file

Overlap is surfaced while runs are in flight, not at merge time. When a conflict does occur, it returns to the agent that made the change, and the merge stays blocked until the result is verifiably clean.

1 · In flight
Overlap detected early
Changed files in every worktree are continuously compared across active runs on the same repository.
Also editing CHANGELOG.md · run 4
2 · First merge
The target advances
One run lands on main. Every finished run built against an earlier target is queued for re-evaluation.
3 · Re-evaluated
Blocked before you act
merge-tree --write-tree against the new target, without touching any working tree. The run is marked as conflicting.
4 · Returned
Resolved by its author
A single action merges the target into the run's branch and hands the conflicted files to the agent's original session, with its full context.
5 · Verified
Re-tested and merged
Tests run again, and the branch is scanned for residual markers. The review shows only the run's own change, measured from the merge-base.

Known limits

Semantic conflicts, where two changes merge cleanly as text but break each other in behavior. Verification currently runs on each branch, not on the merged result.

Prerequisites for unattended merge

Verification on the merged result in an isolated worktree. A merge queue that lands one change at a time. Protected paths and change-size limits that route high-risk work to a reviewer. Until then, merge remains a deliberate human action.
